# ONYX GROUP — витрина и операционная система заказов

Проект сохраняет действующую клиентскую витрину ONYX GROUP и добавляет первый рабочий контур управления дропшиппинг-заказами на Cloudflare Worker + D1 + R2.

## Текущий статус

Работает в действующем сайте:

- витрина, поиск по китайским площадкам, калькулятор, корзина и Telegram-передача;
- загрузка каталога из Cloudflare Worker;
- публичный трекинг;
- расширение Chromium для считывания карточки товара.

Добавлено в этой версии:

- защищённый вход сотрудников и серверные роли `owner`, `manager`, `finance`;
- единый список заказов, поиск, фильтры, ответственный и просроченные действия;
- отдельный тип заказа для конечного клиента и партнёра-дропшиппера без выдуманной партнёрской комиссии;
- клиент, состав заказа и журнал изменений;
- отдельные статусы заказа, оплаты, доставки и заказа поставщику;
- товары, варианты, поставщики, предложения, остатки и срок актуальности;
- проверяемый CSV-импорт предложений;
- распределение одного заказа покупателя между несколькими поставщиками;
- защита заказов и денежных событий от дублей;
- начисления и фактические движения денег отдельно;
- ручная проверка перевода: финансовый сотрудник регистрирует, владелец подтверждает без хранения данных карты;
- отправления карго: менеджер регистрирует, владелец подтверждает статус;
- предварительная и фактическая маржа; неизвестные расходы не подменяются нулём;
- очередь автоматизации, безопасный повтор и остановка правил;
- D1-миграция и тесты сквозных сценариев.

Не включено без отдельного решения владельца:

- автоматический эквайринг и возвраты через платёжный сервис;
- криптовалюта как способ оплаты товара;
- автоматическая отправка заказов поставщикам;
- сообщения клиентам от бота;
- интеграции служб доставки;
- XLSX-импорт без образца реального файла;
- официальный обмен данными с WeChat/WeCom.

## Структура

- `index.html`, `config.js` — действующая клиентская витрина GitHub Pages;
- `src/index.mjs` — API, авторизация, заказы, каталог, финансы и автоматизация;
- `src/admin-shell.mjs` — защищённая русскоязычная панель `/admin`;
- `src/ops-core.mjs` — правила статусов, денег, остатков и импорта;
- `migrations/0001_ops_mvp.sql`, `0002_confirmed_business_model.sql` — схема D1;
- `tests/` — интеграционные тесты с настоящим SQLite-файлом;
- `catalog-core.mjs`, `extractor*`, `popup*`, `manifest.json` — существующий импорт карточек товаров;
- `docs/` — аудит, бизнес-процесс, автоматизация и эксплуатация.

## Проверка локально

Нужен Node.js 22 или новее.

```bash
npm test
npm run check
```

Локальная панель с отдельной тестовой базой:

```bash
ONYX_PREVIEW_SETUP_TOKEN=change-me-local node scripts/local-preview.mjs
```

Откройте `http://localhost:8787/admin`. Первого владельца создайте один раз:

```bash
curl -X POST http://localhost:8787/api/admin/bootstrap \
  -H 'Content-Type: application/json' \
  -H 'X-Setup-Token: change-me-local' \
  --data '{"email":"owner@example.com","name":"Владелец","password":"replace-with-strong-password"}'
```

Локальные данные находятся в `.dev/preview.sqlite` и не попадают в Git.

## Подготовка Cloudflare

1. Установите зависимости: `npm install`.
2. Выполните `npx wrangler login`.
3. Создайте D1: `npx wrangler d1 create onyx-group-ops`.
4. Вставьте выданный `database_id` в `wrangler.toml` вместо `REPLACE_AFTER_RUNNING_WRANGLER_D1_CREATE`.
5. Создайте R2 при необходимости: `npx wrangler r2 bucket create onyx-group-storage`.
6. Сохраните секреты вне репозитория:

```bash
npx wrangler secret put SETUP_TOKEN
npx wrangler secret put ADMIN_TOKEN
```

`SETUP_TOKEN` нужен только для создания первого владельца. `ADMIN_TOKEN` оставлен для совместимости с расширением импорта и должен быть отдельным секретом.

7. Перед миграцией получите точку восстановления:

```bash
npx wrangler d1 time-travel info onyx-group-ops
```

8. Примените схему и разверните Worker:

```bash
npm run db:migrate:remote
npm run deploy
```

9. Если адрес Worker изменился, обновите `API_BASE` в `config.js` и проверьте клиентский сайт.
10. Создайте первого владельца через `/api/admin/bootstrap`, затем удалите или замените `SETUP_TOKEN`.

## Ежедневная работа

1. Откройте `/admin` и разберите «Новые» и «Просроченные действия».
2. Проверьте тип покупателя. Для партнёра пока не применяются специальные цены или комиссии — они должны быть согласованы отдельно.
3. Проверьте цену, остаток и время обновления предложения поставщика. Пишите поставщику в его окне по `Asia/Shanghai`.
4. Если цена изменилась, остаток неизвестен или данные устарели, заказ остаётся на проверке менеджера.
5. Создайте один или несколько черновиков заказов поставщикам.
6. Финансовый сотрудник регистрирует ожидаемый перевод; только владелец подтверждает поступление.
7. Менеджер регистрирует сообщение карго; владелец подтверждает статус и трек-номер.
8. Финансовый сотрудник отдельно записывает остальные начисления и фактические движения денег.
9. Помечайте расходы полными только после учёта закупки, доставки, комиссий, возвратов и известных налогов.
10. Проверяйте очередь автоматизации; повтор допустим только для операций со статусом ошибки.

## Резервное копирование и восстановление

Cloudflare D1 Time Travel включён автоматически. Перед миграциями фиксируйте bookmark. Восстановление перезаписывает текущую базу, поэтому сначала зафиксируйте текущий bookmark и остановите записи.

```bash
npx wrangler d1 time-travel info onyx-group-ops
npx wrangler d1 time-travel restore onyx-group-ops --bookmark=BOOKMARK
```

Для хранения дольше окна Time Travel настройте регулярный экспорт D1 в отдельный R2-бакет или внешнее зашифрованное хранилище. Проверяйте восстановление на отдельной тестовой базе не реже раза в квартал.

План отката миграции:

1. сохранить bookmark до миграции;
2. развернуть обратно совместимую версию Worker;
3. если новая схема уже использовалась, остановить приём заказов;
4. восстановить D1 к bookmark;
5. повторно проверить вход, список заказов и публичное создание заявки.

## Ориентировочная стоимость

Для небольшого пилота Cloudflare Workers, D1 и R2 могут помещаться в бесплатные лимиты. Для рабочего бизнеса разумно заложить минимум **$5 в месяц** на Workers Paid; сверх лимитов стоимость зависит от запросов, строк D1 и объёма изображений R2. Telegram Bot API бесплатен, но сообщения пока отключены. Домен обычно стоит ориентировочно **$10–30 в год** — это рыночное допущение, а не цена конкретного регистратора.

GitHub Pages следует оставить только как временную витрину: официальные ограничения GitHub прямо указывают, что Pages не предназначен для коммерческого сайта, который обслуживает транзакции. До реального запуска перенесите клиентскую витрину на коммерчески допустимый хостинг; Worker и база уже отделены от фронтенда.

Для российского пилота не следует рассчитывать на режим самозанятого: ФНС исключает перепродажу товаров из НПД. До включения реальных платежей нужен ИП/ООО, расчётный счёт и подтверждённая бухгалтером схема договоров. Локальный режим и ручная проверка платежа предназначены только для тестирования процесса.
