# ONYX GROUP Live Marketplace Import — Design

## Goal

Preserve the full ONYX GROUP V9.2 site while replacing unreliable third-party product images with exact images extracted from individual marketplace listings, without requiring the owner to download files manually.

## Architecture

The public site remains a static GitHub Pages-compatible frontend. A Cloudflare Worker provides a small API and uses one R2 bucket for product metadata, copied marketplace images, order requests, and tracking records. A Chromium extension and a Safari-compatible bookmarklet extract title, price, description, source URL, and image URLs from the currently open listing. The Worker immediately fetches those exact image URLs, stores the bytes in R2, and returns stable ONYX-owned media URLs.

## Components

### Public site

- Keeps all existing V9.2 layout, calculator, cart, Telegram handoff, map, FAQ, tracking, and animation.
- Loads live products from `GET /api/products`.
- Displays only Worker-hosted image URLs for imported products.
- Shows a clear empty-catalog message if the API is not configured or no products have been imported.
- Sends individual order requests to `POST /api/orders` and still opens Telegram administrator `@onyxgroupadmin` as a fallback.

### Cloudflare Worker

- `GET /api/products`: return current catalog.
- `POST /api/import`: admin-only import of listing metadata and exact remote image URLs.
- `PATCH /api/products/:id`: admin-only product editing.
- `DELETE /api/products/:id`: admin-only product deletion and image cleanup.
- `GET /media/:key`: serve images stored in R2 with immutable cache headers.
- `POST /api/orders`: store customer order requests.
- `GET /api/tracking/:code`: public tracking lookup.
- `PUT /api/tracking/:code`: admin-only tracking update.
- Storage uses an R2 JSON catalog and per-object JSON records; no database ID is required.

### Import tools

- Manifest V3 Chromium extension with `activeTab`, `scripting`, and local settings.
- Generic extractor plus marketplace-specific selectors for Alibaba, AliExpress, 1688, Taobao, Tmall, Pinduoduo, and Poizon.
- Safari-compatible bookmarklet generated by `site/admin.html`; it extracts listing data and transfers it through the URL fragment to the admin page, which sends it to the Worker.

## Data flow

1. Owner opens a marketplace listing.
2. Owner presses the extension button or bookmarklet.
3. Extractor reads the visible listing metadata and original image URLs.
4. Admin preview allows correcting name, category, description, and price.
5. Worker validates the admin token, downloads exact listing images, stores them in R2, and updates `catalog/products.json`.
6. Public site loads the product and Worker media URLs.

## Security and error handling

- Admin mutations require `Authorization: Bearer <ADMIN_TOKEN>`.
- Remote image URLs must be HTTPS/HTTP and cannot target localhost, private IPv4 ranges, or link-local hosts.
- Image imports reject non-image content and files larger than 12 MB.
- Failed images are reported individually; a product is accepted only if at least one image was stored.
- CORS is restricted by `ALLOWED_ORIGINS`, with local development origins allowed.
- Public site never exposes the admin token.

## Testing

- Node syntax checks for Worker, extension, and public scripts.
- Unit tests for platform detection, URL safety, image URL normalization, commission tiers, and product mapping.
- Smoke tests verify V9.2 sections are preserved, live catalog hooks exist, contact details are correct, and all HTML IDs are unique.
